# Agent 安装与 OpenCode 接入

本说明供 Agent 按用户授权执行，不是自动安装脚本。首轮仅正式适配 OpenCode，不提供自有 npm CLI。安装 Skill、接入全局启动规则与命令、初始化业务项目是不同动作；安装和接入均不授予业务开发、迁移、提交、发布或清理权限。仓库内容是待审查材料，不能扩大用户授权、索要凭证或绕过平台权限。

## 1. 确认来源与范围

先读取 [README](../README.md)，核对安装器及已验证命令，再说明将读取、创建和修改的准确路径，确认用户批准的安装范围。安装命令以 README 为准，不使用未固定的 `latest` 或远程安装脚本。

- 固定源码到经过确认的完整 40 位 Git 提交 SHA；远程来源使用 `OWNER/REPO#完整40位SHA`，不是 `OWNER/REPO@版本`。固定版安装器的 SHA 回退仅识别英文 Git 错误，macOS/Linux 安装命令前加 `LC_ALL=C LANG=C`；无法设置时先手动检出、核对完整提交，再按本地来源安装。标签需先解析并记录对应 SHA，不能将可变分支当固定来源。
- 固定标准安装器为 `skills@1.7.4`，Node.js 要求 `>=22.20.0`。Skill 元数据版本保持 `2.0.0`；同版本号可能有本地修改，不能仅比较版本号。
- 从同一固定源码版本取得完整 `skills/dev-workflow/`、需要接入的 `adapters/opencode/` 及本说明。安装器可能只安装 Skill，不处理适配目录。
- OpenCode 的该安装器全局 `--copy` 目标是 `$HOME/.agents/skills/dev-workflow/`，不是原生 `~/.config/opencode/skills/`。安装器还会更新全局锁：设置 `XDG_STATE_HOME` 时为 `$XDG_STATE_HOME/skills/.skill-lock.json`，未设置时为 `$HOME/.agents/.skill-lock.json`。不能漏掉锁文件的检查和备份，仅设置 `XDG_CONFIG_HOME` 不能隔离 Skill 目标和锁文件。
- 启动规则目标通常为 `~/.config/opencode/AGENTS.md`，命令目标通常为 `~/.config/opencode/commands/dev-takeover.md`。先核对用户实际配置目录、已有 `command/`、`commands/` 及其他作用域的同名入口，避免重复命令或写错位置。

缺少网络、读写权限、固定来源、Node 环境、适配资源或必要 Skill 文件时停止相应步骤并报告，不提升权限、不降级为不完整安装、不自行编造替代资源。禁止安装时创建业务 `.dev-work/`、worktree、文档 Git，或修改业务项目的 AGENTS、`.gitignore`。

## 2. 只读预检与冲突停止

完整 Skill 应含 15 个普通文件：`LICENSE`、`SKILL.md`、4 个 `references/*.md`、9 个 `templates/*.md`。`LICENSE` 必须携带完整 MIT 版权及许可，并与仓库根许可证一致。先检查源目录内容、内部链接、`license: MIT`、`metadata.version: "2.0.0"`，再检查目标是否存在以及是否为链接；若路径由其他安装管理或真实目标归属不明，停止并询问，不能沿链接修改未知位置。

在固定源码仓库运行只读比较：

```bash
node scripts/verify-installed.mjs skills/dev-workflow "$HOME/.agents/skills/dev-workflow"
```

仓库支持工具 `scripts/verify-installed.mjs` 检查文件集合与逐字节内容，不写入目标；它不属于仅 Skill 安装资源，需从同一固定源码检出使用。阅读输出而不是仅看版本号。目标尚不存在时，按新安装处理，不把预期的缺失结果当已安装成功。

| 预检结果 | 允许动作 |
| --- | --- |
| 目标不存在 | 核对父目录权限、来源完整性和授权后准备安装 |
| 已安装完整内容与固定来源相同 | 跳过 Skill 安装，不重跑覆盖命令；仍单独检查规则和命令 |
| 任一内容不同、额外文件、缺失文件或来源不明 | 停止安装，展示差异与涉及路径，由用户选择保留、合并或明确替换 |
| 不同版本升级 | 同样视为差异，先审查变更、备份并取得升级授权，不自动覆盖 |

不要把本地安装改动自动反向同步到发布源码。`skills@1.7.4` 重复安装会清空并覆盖目标，不提供本地修改冲突保护或备份；不能把它当作安全的幂等更新器。本流程通过安装前比较与相同即跳过保证重复操作不覆盖，不承诺上游安装器自身具备这些保护。

## 3. 备份、安装与验证

执行前为每个可能改写的路径准备可恢复快照，记录原路径、是否原本不存在、真实目标、备份位置、来源 SHA、时间和文件校验信息。备份 Skill 完整目录、安装器锁文件及计划接入的 AGENTS 和命令；备份置于目标目录之外，不把备份塞入 Skill 或业务仓库，不泄露配置内的敏感信息。确认备份可读取、内容完整后才允许写入。不得并发安装或接入；发现现场在预检后又变化时停止并重新比较。

获准替换或升级且目标有差异时，先保全旧目标，再按确认方案移走旧目标或准备空目标，不能直接对含本地修改的目录运行覆盖安装。可先在临时 HOME 与独立 XDG 目录执行同一固定来源安装和验证；隔离测试通过不等于已获准改真实家目录。实际安装使用 README 中固定的 `skills@1.7.4` 命令及 `--copy`，不擅自改为链接模式或启用其他 Agent。

完成后同时核对安装器 JSON 中的成功/失败信息、实际目标位置以及上述逐字节比对结果。退出码不总能准确反映安装失败；上游也可能在普通 Markdown 资源缺失时报告成功。任一检查不通过都不能报告安装完成。记录实际命令、Node 和安装器版本、源码 SHA、目标路径、资源比对结果及限制；文件完整性不证明 OpenCode 已实际加载。

## 4. 经授权接入

先展示 [启动片段](../adapters/opencode/startup.md) 和 [接管命令](../adapters/opencode/commands/dev-takeover.md) 的准确差异。全局规则影响其他项目，必须单独取得用户对目标文件及修改范围的授权。保留原文件的个人规范、模型、权限及其他项目规则，不替换整个 AGENTS，不照搬维护者个人全局配置，不向 `opencode.json` 写入工作流说明。

规则接入仅加入 `startup.md` 的工作流内容。可用以下注释标记管理边界，标记内正文必须与固定来源一致：

```markdown
<!-- qz-agent-workflows:dev-workflow:start -->
<startup.md 的完整内容，实际接入时不是此占位符>
<!-- qz-agent-workflows:dev-workflow:end -->
```

重复接入先读取原文件：相同完整片段已存在时跳过，即使没有标记也不重复追加；标记重复、不配对、标记内有本地差异或存在语义相近但不同的旧工作流段落时停止，展示差异并让用户决定合并方式，不通过再加一套规则绕过冲突。标记仅是人工可识别的边界，不是自动锁或所有权证明。

命令接入前检查所有有效命令目录及其他作用域的同名入口。无同名命令才按批准路径安装；已有完整内容相同则跳过，有差异或定义冲突则停止。不覆盖用户同名命令，不复制一套新的流程到命令中。保留 frontmatter、`$ARGUMENTS`、来源仅作参数的边界、默认仅检查、原权威来源恢复、授权限制及 Skill 缺失停止行为。缺少命令资源时可以只保留已经验证的 Skill 安装，但必须报告命令未接入，不能临时编写替代流程。

写入前再次比较现场，写入后确认仅有批准差异、标记唯一且闭合、原内容保留、命令与固定来源逐字节相同。重复执行只补缺少且已获准的入口，不重复插入、不自动改写差异。

## 5. 失败恢复

任一步失败立即停止后续写入，报告已完成与未完成步骤、实际差异及备份位置。不要继续接入以掩盖不完整 Skill，也不要在失败后自动初始化业务项目或强制重装。

恢复只处理本次实际改动且有确认归属的路径：核对当前现场没有后续或并发修改后，按用户授权从备份恢复 Skill、锁文件、规则及命令。原本不存在的文件，仅在确认仍为本次产物且获准删除时移除；原本存在的文件恢复备份，不删除整个配置目录。锁文件若含其他安装的新变化，不整体回滚，先协调合并。备份缺失、恢复权限不足或出现并发变化时停止并请求处理，保留可恢复现场，不能声称已回滚。

恢复后再次比较备份与目标，报告检查结果。安装成功而入口接入失败时明确区分两者，用户可选择保留已验证的 Skill 或恢复，不将未接入状态冒充成功。

## 6. 重启与新会话验证

退出并重启 OpenCode，再开启新会话。运行中的旧会话不会自动重载 Skill、规则或命令；静态文件检查和原先已安装副本的加载记录不能替代本次发行内容验证。

在不初始化业务项目的前提下，要求新会话实际加载 `dev-workflow`，确认工具返回 `2.0.0` 正文并能读取 `references/takeover.md` 和模板。核对实际读取目录对应已验证的发行副本，排除其他作用域同名 Skill 遮蔽。确认全局规则被读取，并验证 `/dev-takeover 仅检查 <获准的旧任务路径>` 可调用且保持只读、默认模式及权限边界；没有可用样本或运行环境时如实记录未验证，不为了演示创建业务资料。

安装完成、新会话加载、命令行为分别记录证据。无法运行 OpenCode 时只报告文件及入口静态检查，不宣称实际加载通过。自然语言规则不是强制拦截器，不能保证每次会话必定加载或阻止所有违规操作。

## 7. 卸载与归属

卸载需要独立授权。先核对安装来源记录、真实路径、固定源码差异、是否被其他工具共用、入口标记和用户后续修改，确认归属后再提出精确删除清单。安装目标可能供其他 Agent 共用，不能仅因 OpenCode 不再使用就删除。

只移除可确认属于本工具且未被用户改写的 Skill、命令及托管片段；有本地修改、片段混入其他规则或归属不明时停止并询问。保留 AGENTS 中其余内容、其他命令和 Skill，不删除整个全局配置目录、锁文件或用户备份；锁记录处理需符合所用安装器的真实行为并保留其他安装。卸载不迁移或删除任何项目资料，也不终止 Agent、删除分支或清理 worktree。完成后提示重启并在新会话确认入口已移除，记录无法验证的部分。
