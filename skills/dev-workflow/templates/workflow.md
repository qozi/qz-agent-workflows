## 存储与入口

本目录是主协调的流程资料，不进入业务 Git，不参与业务 PR 合并。业务根 `.gitignore` 使用 `/.dev-work/` 排除；存在已跟踪历史资料时先批准迁移和停止跟踪，不能仅加规则便宣称完成。文档 Git 可选且独立，业务和文档提交分别授权、分别标识版本。

项目 AGENTS 保留工具 init 或已有项目信息，仅引用本说明，不复制协作规则或任务清单。子 worktree 中没有本目录是正常状态；简单任务或普通 clone 不因缺少本说明而自动初始化。

## 子任务与隔离

仅业务 Git 项目且有大改动、多需求并行或实际冲突风险时建议 worktree，创建前取得用户确认；已有明确同范围授权可复用。不采用隔离时按文件分工，重叠修改串行。

子 Agent 工作区不创建、复制、链接 `.dev-work/`，不初始化文档 Git。主 Agent 派发实际可读的资料路径、需求/任务 ID、范围、完成条件和代码权限。无法读取时回问主 Agent 获取获准摘录，不猜路径或复制完整资料。

子 Agent 只读需求和任务，完成后通知主 Agent，报告代码版本、文件、实际验证及问题；主 Agent 核验后更新任务、审查和验证记录。记录是协作约定，不是文件锁或权限绕过机制。

## 恢复与收尾

已有需求恢复原 ID、任务、代码位置和可用 Agent；旧版来源未批准迁移时按原入口恢复，不并行维护两套状态。需求范围和门槛调整须批准，不使用“部分完成”作为执行任务状态。

业务合并只更新代码交付引用，不搬迁资料到业务 main。资料根目录或文档仓库变更才交接权威来源；清理承载本目录的工作区前检查忽略文件、独立 Git 和可靠备份，不能以业务 Git 干净或文档已本地提交为由直接删除。
